1. Definition und Zweck

AspektBeschreibung
DefinitionDas Domain Name System (DNS) ist ein hierarchisch verteilter Verzeichnisdienst, der menschenlesbare Domainnamen (z. B. geraeteserver.klinik.local) in IP-Adressen auflöst und umgekehrt.
StandardisierungGrundlegend spezifiziert in RFC 1034 und RFC 1035.
ZweckErmöglicht Anwendungen und Nutzern, Systeme über feste, einprägsame Namen anzusprechen, unabhängig von möglichen Änderungen der zugrunde liegenden IP-Adresse.
TransportprotokollPrimär UDP Port 53 für einfache Anfragen; TCP Port 53 für größere Antworten (z. B. Zonentransfer) oder bei aktivierter Absicherung.
Bedeutung im KrankenhausnetzGrundlage dafür, dass Applikations-, Datenbank- und Webserver (siehe Kapitel „Serielle Anbindung“, Abschnitt 10) über stabile Namen statt fest einprogrammierter IP-Adressen angesprochen werden können.

3. DNS-Architektur und Rollen

RolleAufgabe
Stub-ResolverEinfache Client-Komponente auf dem Endgerät, die Anfragen an einen konfigurierten DNS-Server weiterreicht.
Rekursiver ResolverÜbernimmt die vollständige Auflösung im Auftrag des Clients, indem er selbst iterative Anfragen an mehrere Server stellt.
Root-ServerVerweisen auf die zuständigen Server der jeweiligen Top-Level-Domain.
TLD-ServerVerweisen auf die autoritativen Server der jeweiligen Second-Level-Domain.
Autoritativer ServerHält die tatsächlichen Ressourcendatensätze einer Zone und beantwortet Anfragen dazu verbindlich.

4. Ablauf einer DNS-Auflösung

Der rekursive Resolver stellt im Auftrag des Clients nacheinander iterative Anfragen an Root-, TLD- und autoritativen Server, bis die IP-Adresse ermittelt ist.
AnfrageartBeschreibung
Rekursive AnfrageDer Client bittet den Resolver um die vollständige Auflösung; der Resolver liefert entweder das Ergebnis oder eine Fehlermeldung – nicht nur einen Verweis.
Iterative AnfrageDer angefragte Server liefert entweder die Antwort oder einen Verweis auf einen zuständigeren Server; der Anfragende (i. d. R. der rekursive Resolver) stellt die nächste Anfrage selbst.

7. Caching und TTL

AspektBeschreibung
TTL (Time to Live)Vom autoritativen Server je Ressourcendatensatz festgelegte Gültigkeitsdauer, nach der ein zwischengespeicherter Eintrag erneut abgefragt werden muss.
Caching am ResolverRekursive Resolver speichern Antworten für die Dauer der TTL zwischen, um wiederholte vollständige Auflösungen zu vermeiden und die Antwortzeit zu verkürzen.
Abwägung der TTL-LängeKurze TTL-Werte ermöglichen schnelle Änderungen (z. B. bei Serverumzug), erhöhen jedoch die Anzahl der Anfragen; lange TTL-Werte reduzieren die Last, verzögern aber die Verbreitung von Änderungen.

9. DNS in der Krankenhaus-IT

AspektBeschreibung
Interner DNS-ServerKrankenhäuser betreiben i. d. R. eigene, interne DNS-Server für eine interne Domain (z. B. klinik.local), die nicht öffentlich auflösbar ist.
Split-DNSFür dieselbe Domain existieren unterschiedliche Antworten je nachdem, ob die Anfrage aus dem internen Netz oder von extern kommt – ermöglicht z. B. abweichende Adressen für interne Server und ein öffentliches Patientenportal.
Namensauflösung im RechenzentrumGeräteserver, Applikationsserver, Datenbankserver und Webserver werden über feste interne Namen statt fest kodierter IP-Adressen angesprochen (siehe Kapitel „Serielle Anbindung“, Abschnitt 10), was Wartung und Ausfallsicherheit erleichtert.
NamenskonventionenEinheitliche Benennungsschemata (z. B. nach Funktion, Standort, Umgebung) erleichtern Administration und Fehlersuche.

10. Dynamic DNS und DHCP

AspektBeschreibung
ProblemstellungBei dynamisch per DHCP vergebenen IP-Adressen (siehe Kapitel „DHCP“) müsste der zugehörige DNS-Eintrag bei jeder Änderung manuell gepflegt werden.
Dynamic DNS Update (DDNS)Der DHCP-Server (oder der Client selbst) aktualisiert automatisch den passenden DNS-Eintrag, sobald eine neue Adresse vergeben wurde.
Praxisrelevanz in der MedizintechnikFür Geräte mit fester MAC-basierter Reservierung (siehe Kapitel „DHCP“, Abschnitt 10) bleibt der DNS-Eintrag ohnehin stabil; DDNS ist vor allem für dynamisch adressierte Clientgeräte relevant.

11. Sicherheit

Bedrohung / MaßnahmeBeschreibung
DNS-SpoofingEin Angreifer sendet gefälschte DNS-Antworten, um einen Client auf ein bösartiges Ziel umzuleiten.
Cache-PoisoningEinschleusen falscher Einträge in den Cache eines rekursiven Resolvers, sodass dieser für eine gewisse Zeit falsche Antworten ausliefert.
DNSSECErweiterung des DNS um kryptographische Signaturen, mit denen die Authentizität und Integrität von Antworten überprüft werden kann.
DNS-Firewalling / Response Policy ZonesBlockierung von Anfragen zu bekanntermaßen bösartigen Domains bereits auf DNS-Ebene, bevor eine Verbindung überhaupt aufgebaut wird.
Beschränkung rekursiver AnfragenInterne DNS-Server sollten rekursive Anfragen nur aus vertrauenswürdigen Netzsegmenten zulassen, um Missbrauch (z. B. für DDoS-Verstärkungsangriffe) zu verhindern.

12. Hochverfügbarkeit

KonzeptBeschreibung
Primary/Secondary-ServerEin primärer Server hält die maßgebliche Zonendatei; ein oder mehrere sekundäre Server halten eine replizierte Kopie und können bei Ausfall des Primärservers weiterhin Anfragen beantworten.
Zonentransfer (AXFR/IXFR)AXFR überträgt die vollständige Zone, IXFR nur die seit der letzten Synchronisation geänderten Einträge, vom primären an sekundäre Server.
AnycastMehrere DNS-Server werden unter derselben IP-Adresse betrieben; Anfragen werden automatisch an den topologisch nächstgelegenen Server geleitet – u. a. bei den Root-Servern im Einsatz.
Relevanz für KliniknetzeDer Ausfall des internen DNS-Dienstes kann die Erreichbarkeit sämtlicher namensbasiert angesprochener Server (Applikations-, Datenbank-, Webserver) beeinträchtigen; redundante DNS-Server sind daher Standard.

14. Begriffe und Zusammenfassung

BegriffBedeutung
FQDNFully Qualified Domain Name; vollständiger, eindeutiger Name eines Systems innerhalb der DNS-Hierarchie.
ResolverKomponente, die eine DNS-Anfrage im Auftrag eines Clients durchführt.
ZoneAdministrativ zusammengehöriger Teil des DNS-Namensraums mit eigener Zonendatei.
TTLTime to Live; Gültigkeitsdauer eines zwischengespeicherten DNS-Eintrags.
DNSSECSicherheitserweiterung des DNS zur kryptographischen Absicherung von Antworten.
Split-DNSBereitstellung unterschiedlicher DNS-Antworten je nach Herkunft der Anfrage (intern/extern).
Fazit: DNS ist ein unverzichtbarer Verzeichnisdienst, der die Namensauflösung für sämtliche im Krankenhausnetz betriebenen Systeme bereitstellt. Im Zusammenspiel mit DHCP (dynamische Adressvergabe), VLANs (Netzsegmentierung) und Firewalls (Zugriffskontrolle) bildet DNS einen zentralen Baustein der Netzwerkinfrastruktur für Medizintechnik und Klinik-IT.
