Gateway → Kommunikationsserver

Nach der Netzwerk- und Gateway-Ebene können Daten an einen Kommunikationsserver übergeben werden. Der Kommunikationsserver ist eine zentrale Integrationskomponente, die Nachrichten zwischen medizinischen Systemen annimmt, verarbeitet, protokolliert und an definierte Zielsysteme weiterleitet.

Abgrenzung: Ein Router/Gateway stellt primär Netzwerk- oder Transportverbindungen her. Ein Kommunikationsserver arbeitet zusätzlich auf der Ebene von Nachrichten, Schnittstellen und Integrationsregeln.

1. Typischer Ablauf

Gerät → Gateway / Routing → Kommunikationsserver → Zielapplikation
  1. Das Gerät baut eine Netzwerkverbindung zum konfigurierten Ziel auf.
  2. Routing und Firewall ermöglichen den Datenverkehr.
  3. Der Kommunikationsserver nimmt die Nachricht bzw. das Protokoll entgegen.
  4. Die Nachricht wird anhand ihrer Schnittstelle und Routingregeln verarbeitet.
  5. Das Zielsystem erhält die Daten über die vorgesehene Schnittstelle.

2. Aufgaben des Kommunikationsservers

  • Annahme eingehender Nachrichten
  • Routing anhand von Absender, Empfänger, Nachrichtentyp oder Inhalt
  • Protokoll- und Formatvermittlung
  • Zwischenspeicherung bei temporären Störungen
  • Quittierungen und Fehlerbehandlung
  • Logging und Überwachung des Nachrichtenflusses
  • Wiederholung fehlgeschlagener Übertragungen, sofern vorgesehen

4. Beispiel Röntgen

Ein Röntgengerät kann seine Bilddaten an einen DICOM-Router senden. Dieser übernimmt das Routing zum PACS. Für andere Nachrichten kann zusätzlich ein Kommunikationsserver eingesetzt werden.

KIS / RIS → Worklist → Röntgengerät → DICOM → Gateway / DICOM-Router → PACS

Der Kommunikationsserver kann parallel oder nachgelagert für HL7-Nachrichten eingesetzt werden, beispielsweise für Auftrags-, Status- oder Befundinformationen.

5. Nachrichtenverarbeitung

Eine Nachricht durchläuft typischerweise mehrere Schritte:

Empfang → Validierung → Routing → Transformation (falls nötig) → Zielverbindung → Quittierung → Logging

Eine Transformation ist nur dann erforderlich, wenn unterschiedliche Systeme verschiedene Formate oder Nachrichtenstrukturen benötigen. Jede Transformation sollte nachvollziehbar dokumentiert werden.

6. Zuverlässigkeit und Ausfallsicherheit

Kommunikationsserver können Nachrichten zeitweise puffern, wenn ein Zielsystem nicht erreichbar ist. Je nach Produkt und Konfiguration sind Wiederholungsmechanismen, Fehlerqueues, Hochverfügbarkeit und Monitoring möglich. Eine Queue ersetzt jedoch keine dauerhafte Archivierung.

7. Sicherheit

Die Kommunikation sollte auf notwendige Systeme, Ports und Protokolle begrenzt werden. Zugriffe auf Administrationsoberflächen müssen geschützt werden. Logs können personenbezogene oder medizinische Informationen enthalten und müssen entsprechend geschützt und aufbewahrt werden.

8. Fehleranalyse

  1. Gateway und Routing prüfen.
  2. Firewall und TCP-Port prüfen.
  3. Erreichbarkeit des Kommunikationsservers prüfen.
  4. Schnittstellenkonfiguration und Endpunkte kontrollieren.
  5. Nachrichten- und Verbindungslogs prüfen.
  6. Fehlerqueue bzw. Retry-Status kontrollieren.
  7. Zielapplikation und deren Schnittstelle prüfen.

9. Einordnung

Gerät → Netzwerk → Gateway → Kommunikationsserver → Applikation → Datenbank / PACS / VNA → Archiv / Backup
