Kommunikationsserver → Applikation

Die Applikation ist die Ebene, auf der die empfangenen medizinischen Informationen fachlich genutzt werden. Der Kommunikationsserver stellt dabei die technische Verbindung her; die Applikation verarbeitet die Daten entsprechend ihrer klinischen Aufgabe.

1. Vom Server zur Anwendung

Kommunikationsserver → Schnittstelle → Applikation → Verarbeitung → Datenhaltung

Die Übergabe kann beispielsweise über HL7 v2, FHIR, DICOM, REST-APIs oder andere produktspezifische Schnittstellen erfolgen. Welche Schnittstelle eingesetzt wird, hängt von der Anwendung und der Systemarchitektur ab.

2. Was macht die Applikation?

  • Sie nimmt strukturierte Informationen entgegen.
  • Sie prüft fachliche Pflichtfelder und Plausibilität.
  • Sie ordnet Informationen einem Patienten, Fall oder Auftrag zu.
  • Sie stellt Daten für Benutzer oder Folgeprozesse bereit.
  • Sie speichert relevante Informationen in Datenbanken oder angebundenen Speichern.
  • Sie erzeugt bei Bedarf neue Nachrichten oder Befunde.

3. Beispiel: RIS

Das Radiologieinformationssystem (RIS) verarbeitet unter anderem Untersuchungsaufträge, Termin- und Statusinformationen sowie Befunde. Ein Kommunikationsserver kann HL7-Nachrichten an das RIS übergeben.

KIS → HL7 → Kommunikationsserver → RIS

Nach der Verarbeitung kann das RIS beispielsweise einen Untersuchungsstatus zurückmelden oder einen Befund an ein anderes System übergeben.

4. Beispiel: PACS

Bei Bilddaten ist die Applikation häufig das PACS bzw. ein daran angebundener Dienst. Das Röntgengerät sendet DICOM-Objekte an einen DICOM-Router oder direkt an das PACS. Das PACS prüft die Objekte, ordnet sie der Untersuchung zu und speichert sie im vorgesehenen Bildspeicher.

Röntgengerät → DICOM → DICOM-Router → PACS → Bildspeicher

5. Datenbank und Bildspeicher unterscheiden

Eine klinische Applikation kann Metadaten in einer relationalen Datenbank speichern, während große medizinische Dateien in einem separaten Objekt-, Datei- oder spezialisierten Bildspeicher liegen. Bei einem PACS können beispielsweise Patienten-, Studien- und Serieninformationen in Datenbankstrukturen verwaltet werden, während die eigentlichen DICOM-Objekte im Bildspeicher liegen.

6. Befundfluss

Bild → PACS Viewer → Befundapplikation / RIS → signierter Befund → Kommunikationsschnittstelle → KIS

Der Befund wird in der dafür vorgesehenen Anwendung erstellt und nach der Freigabe über die konfigurierte Integrationsschnittstelle an das KIS übertragen. Je nach Architektur kann dabei HL7 v2, FHIR oder eine andere Schnittstelle eingesetzt werden.

7. Speicherung, Archivierung und Backup

EbeneZweck
ApplikationsdatenbankStrukturierte Daten und Metadaten für die Anwendung
Online-/PrimärspeicherSchneller Zugriff auf aktuelle Daten und Bilder
LangzeitarchivLangfristige Aufbewahrung entsprechend organisatorischer und rechtlicher Vorgaben
BackupWiederherstellung nach Datenverlust oder technischen Ausfällen
ReplikationZusätzliche Kopie auf einem getrennten System oder Standort

Backup und Archivierung erfüllen unterschiedliche Aufgaben. Ein Backup dient primär der Wiederherstellung; ein Archiv ist für die langfristige Verfügbarkeit und Aufbewahrung vorgesehen.

8. Monitoring und Fehleranalyse

  1. Prüfen, ob der Kommunikationsserver die Nachricht angenommen hat.
  2. Prüfen, ob die Nachricht korrekt geroutet wurde.
  3. Applikationslogs und Schnittstellenstatus kontrollieren.
  4. Patienten-/Auftragszuordnung prüfen.
  5. Datenbank- und Speicherstatus prüfen.
  6. Bei Befunden zusätzlich Freigabe- und Übertragungsstatus prüfen.

9. Gesamtzusammenhang

Gerät → Netzwerk → Gateway → Kommunikationsserver → Applikation → Datenbank / Bildspeicher → Archiv / Backup
