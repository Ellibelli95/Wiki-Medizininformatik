Gerät → Gateway

Ein Gateway bildet eine Übergangsstelle zwischen einem medizinischen Gerät bzw. einem Gerätesegment und einem nachgelagerten Netzwerk- oder Anwendungssystem. Es kann dabei Netzwerkverkehr weiterleiten, Protokolle vermitteln oder als technische Integrationskomponente dienen.

Wichtig: Gateway ist kein einheitlich definierter Produkttyp. Je nach Architektur kann damit ein Router, ein Sicherheitsgateway, ein DICOM-Router oder eine Integrationskomponente gemeint sein. Die konkrete Funktion muss in der jeweiligen Umgebung dokumentiert werden.

1. Weg vom Gerät zum Gateway

Das medizinische Gerät ist zunächst über Ethernet oder WLAN an das Krankenhausnetz angebunden. Über Switch, Access Point und VLAN wird festgelegt, in welchem Netzsegment sich das Gerät befindet. Das Gerät besitzt eine IP-Adresse, entweder statisch oder über DHCP.

Medizinisches Gerät → Switch / Access Point → VLAN → Routing / Gateway → Zielnetz

Wenn das Zielsystem in einem anderen IP-Netz liegt, wird der Datenverkehr normalerweise an das konfigurierte Standardgateway des Geräts gesendet. Router oder Layer-3-Switch übernehmen anschließend die Weiterleitung zwischen Netzen. Firewalls oder ACLs können die Verbindung zusätzlich begrenzen.

2. Rolle eines Gateways in der Medizin-IT

  • Routing: Weiterleitung von IP-Paketen zwischen unterschiedlichen Netzsegmenten.
  • Segmentierung: Trennung von Medizingeräten, Arbeitsplatzrechnern, Servern und Managementsystemen.
  • Sicherheit: Einschränkung erlaubter Verbindungen über Firewall-Regeln oder ACLs.
  • Protokollvermittlung: In speziellen Integrationslösungen kann ein Gateway Daten zwischen unterschiedlichen technischen Protokollen vermitteln.
  • Datenrouting: Ein DICOM-Router kann medizinische Bilddaten abhängig von Regeln an PACS, VNA oder weitere Systeme verteilen.

3. Beispiel: Röntgengerät

Ein Röntgengerät steht beispielsweise in einem separaten Medizin-VLAN. Die Netzwerkkonfiguration enthält IP-Adresse, Subnetzmaske, Standardgateway und gegebenenfalls DNS-Server. Das Gerät kann einen DICOM-Dienst eines PACS oder DICOM-Routers erreichen, sofern Routing und Firewall die Verbindung erlauben.

Röntgengerät → Medizin-VLAN → Firewall / Routing → DICOM-Router → PACS / VNA

Für DICOM wird auf der Zielseite typischerweise eine Kombination aus AE Title, IP-Adresse bzw. Hostname und TCP-Port konfiguriert. Diese Parameter müssen auf beiden Seiten zusammenpassen.

4. Gateway und DICOM

Ein DICOM-Router kann als vermittelnde Instanz zwischen Modalitäten und Bildarchiven eingesetzt werden. Das Gerät sendet die Studie an den Router. Der Router nimmt die DICOM-Verbindung an, prüft bzw. verarbeitet die Nachricht und leitet sie entsprechend seiner Routingregeln weiter.

Dadurch kann beispielsweise verhindert werden, dass jede Modalität direkt mit mehreren PACS-Systemen kommunizieren muss. Gleichzeitig lassen sich Routingregeln, Protokollierung und Weiterleitungen zentral verwalten.

6. Sicherheit

Medizinische Geräte sollten nur die Netzwerkverbindungen erhalten, die für ihren Betrieb notwendig sind. Typische Maßnahmen sind getrennte VLANs, restriktive Firewallregeln, kontrollierter Administrationszugriff, Protokollierung und Überwachung. Änderungen an IP-, VLAN-, Gateway- und DICOM-Konfigurationen sollten nachvollziehbar dokumentiert werden.

7. Fehleranalyse

  1. Physische Verbindung bzw. WLAN-Verbindung prüfen.
  2. IP-Adresse, Subnetz und Standardgateway prüfen.
  3. VLAN-Zuordnung und Routing prüfen.
  4. Firewall-/ACL-Regeln und benötigte TCP-Ports prüfen.
  5. DICOM AE Title und Zieladresse kontrollieren.
  6. Erreichbarkeit des Gateways bzw. Zielsystems testen.
  7. DICOM-Logs auf Association-, Transfer- und Fehlermeldungen prüfen.

8. Einordnung im gesamten Datenfluss

Gerät → Netzwerk → Gateway / DICOM-Router → Kommunikationsserver → Applikation → Datenbank / PACS / VNA → Archiv / Backup

Das Gateway ist damit eine mögliche technische Übergangsstelle. Es ersetzt nicht automatisch den Kommunikationsserver oder die Anwendungsschicht.
