JSON

JSON (JavaScript Object Notation) ist ein leichtgewichtiges, textbasiertes Datenformat zur strukturierten Darstellung und Übertragung von Daten. In der Medizininformatik spielt JSON insbesondere bei Webanwendungen, REST-APIs, Microservices und der Kommunikation zwischen verschiedenen Softwaresystemen eine wichtige Rolle.

1. Grundlagen

JSON steht für JavaScript Object Notation. Obwohl JSON ursprünglich aus dem JavaScript-Umfeld stammt, ist das Format heute unabhängig von einer bestimmten Programmiersprache. Viele Programmiersprachen stellen Bibliotheken bereit, mit denen JSON-Daten erzeugt, gelesen, verändert und verarbeitet werden können.

Das zentrale Ziel von JSON ist es, strukturierte Informationen in einer für Menschen lesbaren und für Programme leicht verarbeitbaren Form darzustellen.

Typische Einsatzbereiche

  • Übertragung von Daten zwischen Browser und Server
  • REST- und Web-APIs
  • Kommunikation zwischen Softwarekomponenten
  • Konfiguration von Anwendungen
  • Speicherung strukturierter Daten
  • Datenaustausch in vernetzten medizinischen Informationssystemen

2. Aufbau und Syntax

Ein JSON-Dokument besteht aus strukturierten Daten. Die wichtigsten Bausteine sind Objekte, Arrays und verschiedene primitive Datentypen.

Ein Objekt wird mit geschweiften Klammern { } dargestellt. Innerhalb eines Objekts werden Eigenschaften als Schlüssel-Wert-Paare angegeben:

{
  "patientId": "P10025",
  "name": "Max Mustermann",
  "alter": 42
}

Der Schlüssel steht in doppelten Anführungszeichen. Schlüssel und Wert werden durch einen Doppelpunkt getrennt. Mehrere Eigenschaften werden durch Kommata getrennt.

Merksatz: JSON beschreibt vor allem die Struktur von Daten – nicht deren fachliche Bedeutung. Die Bedeutung entsteht durch die Anwendung bzw. das verwendete Datenmodell.

4. Objekte

Objekte sind die wichtigste Struktur für benannte Informationen. Ein Objekt kann mehrere Eigenschaften enthalten:

{
  "patient": {
    "id": "P10025",
    "geburtsjahr": 1982,
    "station": "Kardiologie"
  }
}

Durch die Verschachtelung können komplexe Informationsstrukturen abgebildet werden. Dabei sollte die Struktur möglichst klar und konsistent bleiben.

5. Arrays

Ein Array ist eine geordnete Liste und wird mit eckigen Klammern [ ] dargestellt.

{
  "diagnosen": [
    "Hypertonie",
    "Diabetes mellitus Typ 2",
    "Vorhofflimmern"
  ]
}

Arrays können auch Objekte enthalten. Dadurch lassen sich beispielsweise mehrere Untersuchungen oder Messwerte darstellen:

{
  "messungen": [
    {
      "zeit": "08:00",
      "wert": 120,
      "einheit": "mmHg"
    },
    {
      "zeit": "12:00",
      "wert": 125,
      "einheit": "mmHg"
    }
  ]
}

6. Verschachtelte Datenstrukturen

Objekte und Arrays können miteinander kombiniert werden. Dadurch lassen sich auch umfangreiche Datenmodelle abbilden.

{
  "patient": {
    "id": "P10025",
    "name": "Max Mustermann",
    "aufenthalte": [
      {
        "station": "Innere Medizin",
        "aufnahme": "2026-09-10"
      },
      {
        "station": "Kardiologie",
        "aufnahme": "2026-09-14"
      }
    ]
  }
}
Prüfungsrelevant: Beim Lesen verschachtelter JSON-Strukturen muss immer zwischen Objektzugriff und Array-Zugriff unterschieden werden. Objekte besitzen benannte Schlüssel; Arrays besitzen Positionen bzw. Indizes.

7. JSON und JavaScript

JSON und JavaScript sind eng miteinander verwandt, aber nicht identisch. JSON ist ein Datenformat. JavaScript ist eine Programmiersprache.

In JavaScript kann eine JSON-Zeichenkette mit JSON.parse() in ein JavaScript-Objekt umgewandelt werden:

const text = '{"name":"Anna","alter":30}';

const daten = JSON.parse(text);

console.log(daten.name);

Umgekehrt kann ein JavaScript-Objekt mit JSON.stringify() in eine JSON-Zeichenkette umgewandelt werden:

const daten = {
  name: "Anna",
  alter: 30
};

const text = JSON.stringify(daten);

8. JSON im Web

Bei Webanwendungen wird JSON häufig verwendet, um Daten zwischen Frontend und Backend auszutauschen. Ein Browser kann beispielsweise eine Anfrage an einen Server senden und eine JSON-Antwort erhalten.

GET /api/patienten/P10025

{
  "id": "P10025",
  "name": "Max Mustermann",
  "status": "stationär"
}

Dadurch können HTML-Oberfläche, JavaScript-Anwendung und Backend logisch voneinander getrennt werden.

9. JSON und REST-APIs

REST-APIs verwenden häufig HTTP zur Kommunikation und JSON als Format für die übertragenen Daten. Typische HTTP-Methoden sind:

  • GET – Daten abrufen
  • POST – neue Daten übertragen
  • PUT – vorhandene Daten vollständig aktualisieren
  • PATCH – vorhandene Daten teilweise aktualisieren
  • DELETE – Daten löschen

Ein API-Aufruf kann beispielsweise strukturierte Patientendaten zurückgeben. Entscheidend ist dabei nicht nur das JSON-Format, sondern auch die fachliche Definition der enthaltenen Felder.

10. JSON in der Medizininformatik

In medizinischen IT-Systemen können JSON-basierte Schnittstellen beispielsweise für Webanwendungen, Terminverwaltung, Dokumentation, Geräteanbindung oder Integrationsplattformen eingesetzt werden.

Ein einfaches, bewusst vereinfachtes Beispiel:

{
  "patient": {
    "id": "P10025"
  },
  "vitalwerte": {
    "temperatur": {
      "wert": 37.1,
      "einheit": "°C"
    },
    "puls": {
      "wert": 72,
      "einheit": "bpm"
    }
  }
}
Wichtig: Dieses Beispiel ist ein vereinfachtes Lehrbeispiel und kein vollständiges medizinisches Datenmodell. In realen Systemen müssen definierte Standards, Profile, Terminologien, Datenschutz- und Sicherheitsanforderungen berücksichtigt werden.

11. JSON und medizinische Standards

JSON ist zunächst nur ein allgemeines Datenformat. Medizinische Interoperabilität benötigt zusätzlich festgelegte Strukturen, Bedeutungen und Regeln. Ein bekanntes Beispiel ist HL7 FHIR, das Ressourcen und deren Inhalte standardisiert und unter anderem JSON als Darstellungsformat unterstützt.

Damit zwei Systeme medizinische Daten korrekt austauschen können, reicht es deshalb nicht aus, dass beide Systeme „JSON können“. Sie müssen sich auch über die Bedeutung, Struktur und zulässigen Werte der übertragenen Daten verständigen.

12. Validierung

Bei der Verarbeitung von JSON sollte überprüft werden, ob die Daten syntaktisch korrekt sind und ob sie dem erwarteten Datenmodell entsprechen.

Ein syntaktisch gültiges JSON-Dokument kann trotzdem fachlich ungeeignet sein. Beispielsweise kann ein Feld fehlen, einen falschen Datentyp besitzen oder einen unerwarteten Wert enthalten.

Für strukturierte Prüfungen kann beispielsweise ein Schema-Ansatz wie JSON Schema verwendet werden.

13. Häufige Syntaxfehler

  • fehlende oder überzählige Kommata
  • einfache statt doppelte Anführungszeichen
  • fehlende geschweifte oder eckige Klammern
  • fehlender Doppelpunkt zwischen Schlüssel und Wert
  • nicht korrekt geschachtelte Strukturen
  • ungültige Werte

Beispiel eines Fehlers:

{
  "name": "Max Mustermann",
  "alter": 42,
}

Das abschließende Komma nach 42 ist in diesem JSON-Objekt nicht zulässig.

14. Sicherheit und Datenschutz

JSON selbst bietet keine automatische Verschlüsselung und keinen Datenschutz. Es ist lediglich ein Datenformat. Werden sensible medizinische Daten übertragen, müssen die Kommunikationswege, Zugriffsrechte, Authentifizierung, Protokollierung und Speicherung entsprechend abgesichert werden.

Besonders bei Gesundheitsdaten ist darauf zu achten, dass personenbezogene Informationen nur im erforderlichen Umfang verarbeitet und geschützt werden.

Sicherheitsregel: Niemals davon ausgehen, dass Daten sicher sind, nur weil sie als JSON übertragen werden. Sicherheit entsteht durch die gesamte technische und organisatorische Infrastruktur.

15. Fehleranalyse und Debugging

Bei Problemen mit JSON sollte die Fehlersuche schrittweise erfolgen:

  1. Ist das JSON syntaktisch gültig?
  2. Entspricht die Struktur dem erwarteten Schema?
  3. Sind Datentypen korrekt?
  4. Sind alle erforderlichen Felder vorhanden?
  5. Wird das richtige API-Endpunkt angesprochen?
  6. Stimmen HTTP-Methode und Request-Header?
  7. Welche Antwort liefert der Server?
  8. Enthalten Logs Hinweise auf die Fehlerursache?

16. Praxisbeispiel: Anfrage und Antwort

Eine Webanwendung könnte eine Liste von Patienten über eine API abrufen. Das Backend liefert beispielsweise:

{
  "patients": [
    {
      "id": "P10001",
      "station": "A1"
    },
    {
      "id": "P10002",
      "station": "B2"
    }
  ]
}

Das Frontend kann diese Daten anschließend einlesen und in einer Benutzeroberfläche darstellen.

18. Zusammenfassung

  • JSON ist ein textbasiertes Format für strukturierte Daten.
  • Die zentralen Strukturen sind Objekte und Arrays.
  • JSON kann verschachtelte Datenstrukturen darstellen.
  • Im Web wird JSON häufig zwischen Frontend und Backend übertragen.
  • REST-APIs verwenden JSON sehr häufig als Austauschformat.
  • JSON selbst definiert keine medizinische Bedeutung.
  • Für medizinische Interoperabilität sind zusätzliche Standards und Datenmodelle erforderlich.
  • JSON ist weder automatisch verschlüsselt noch automatisch sicher.
  • Syntax und fachliche Struktur sollten validiert werden.

20. Merksätze für die Vorlesung

1. JSON ist ein Datenformat, keine Programmiersprache.

2. Objekte beschreiben benannte Eigenschaften, Arrays beschreiben geordnete Listen.

3. Syntaktisch gültiges JSON bedeutet nicht automatisch fachlich korrekte Daten.

4. JSON ermöglicht Datenaustausch – die fachliche Bedeutung muss durch ein Datenmodell oder einen Standard definiert werden.

5. JSON selbst sorgt nicht für Datenschutz oder Verschlüsselung.

Praxis und Fehleranalyse

Bei der praktischen Arbeit sollte JSON zunächst als Datenstruktur betrachtet werden. Für die Fehlersuche sind Syntax, Struktur, Datentypen, Schnittstelle und fachliche Bedeutung getrennt zu überprüfen. Besonders bei medizinischen Anwendungen muss zusätzlich betrachtet werden, welche Daten verarbeitet werden, wer darauf zugreifen darf und welcher Standard für den Austausch verwendet wird.
