1. Was ist eine API?

AspektBeschreibung
DefinitionEine API (Application Programming Interface, Programmierschnittstelle) definiert, wie Softwarekomponenten miteinander kommunizieren können, ohne dass die jeweilige interne Implementierung bekannt sein muss.
ZweckKapselung von Funktionalität hinter einer stabilen, dokumentierten Schnittstelle, die unabhängig von internen Änderungen weiterverwendet werden kann.
Web-APIIm Web-Kontext meist eine über HTTP erreichbare Schnittstelle, über die ein Client (Browser, App, anderes System) Daten abrufen oder verändern kann.

2. Arten von APIs

ArtBeispielBeschreibung
Web-APIREST-Schnittstelle eines Servers (siehe Kapitel „REST“)Über HTTP erreichbare Schnittstelle zwischen Client und Server
Browser-APIDOM-API, Fetch-API, Geolocation-APIVom Browser bereitgestellte Schnittstellen, die per JavaScript angesprochen werden (siehe Kapitel „JavaScript“)
Bibliotheks-APISchnittstelle einer JavaScript- oder Programmiersprachen-BibliothekDefiniert, welche Funktionen/Methoden eine Bibliothek nach außen anbietet
Betriebssystem-APIDateisystemzugriff, Netzwerk-API des BetriebssystemsSchnittstelle zwischen Anwendungssoftware und Betriebssystem

3. Client-Server-Kommunikation über Web-APIs

Grundprinzip einer Web-API: Der Client sendet eine HTTP-Anfrage, der Server antwortet mit strukturierten Daten (häufig JSON, siehe Kapitel „JSON“).

4. Wichtige Browser-APIs

APIZweck
DOM-APIProgrammatischer Zugriff auf Struktur und Inhalt der geladenen Webseite (siehe Kapitel „HTML“, Abschnitt 9).
Fetch-APIModerne, Promise-basierte Schnittstelle zum Absetzen von HTTP-Anfragen aus JavaScript heraus.
Geolocation-APIErmittlung des Gerätestandorts mit Zustimmung des Nutzers.
Constraint Validation APIProgrammatische Formularvalidierung (siehe Kapitel „JavaScript“, Abschnitt 9).

5. AJAX als Vorläufer

AspektBeschreibung
DefinitionAJAX (Asynchronous JavaScript and XML) bezeichnet die Technik, im Hintergrund Daten vom Server nachzuladen, ohne die gesamte Seite neu zu laden.
Historische EinordnungUrsprünglich über das XMLHttpRequest-Objekt realisiert; heute größtenteils durch die modernere Fetch-API abgelöst.
BedeutungAJAX war die technische Grundlage für die Entwicklung interaktiver Single-Page-Anwendungen und moderner API-Kommunikation.

6. API-Design-Prinzipien

PrinzipBeschreibung
KonsistenzEinheitliche Benennung von Endpunkten, Parametern und Antwortformaten erleichtert die Nutzung durch Entwickler.
VersionierungExplizite Versionsangaben (z. B. im URL-Pfad /v1/…) ermöglichen Weiterentwicklung, ohne bestehende Clients zu brechen.
DokumentationMaschinenlesbare Spezifikationen (z. B. OpenAPI) erleichtern automatische Codegenerierung und Testung.
IdempotenzWiederholte, identische Anfragen sollten denselben Zustand erzeugen wie eine einmalige Anfrage – relevant für zuverlässige Fehlerbehandlung.

7. Authentifizierung von APIs

VerfahrenBeschreibung
API-KeyStatischer, dem Client zugewiesener Schlüssel, der bei jeder Anfrage mitgesendet wird; einfach, aber vergleichsweise unflexibel.
OAuthAutorisierungsframework, das einer Anwendung delegierten Zugriff auf Ressourcen im Namen eines Nutzers gewährt, ohne dessen Zugangsdaten offenzulegen.
JWT (JSON Web Token)Signiertes, selbstbeschreibendes Token, das Identitäts- und Berechtigungsinformationen enthält und vom Server ohne zusätzliche Datenbankabfrage geprüft werden kann (siehe Kapitel „Web Security“).

8. APIs in der Medizin-IT

AspektBeschreibung
HL7 FHIRModerner, RESTful-API-basierter Standard zum Austausch strukturierter Gesundheitsdaten zwischen Informationssystemen.
GeräteanbindungGateways und Geräteserver (siehe Kapitel „Serielle Anbindung“, Abschnitt 9) stellen die Daten vernetzter Medizingeräte häufig über eine interne API dem Applikationsserver bereit.
InteroperabilitätStandardisierte APIs sind zentrale Voraussetzung für die Integration heterogener Systeme unterschiedlicher Hersteller im Krankenhaus.

9. Fehlerbehandlung

AspektBeschreibung
HTTP-StatuscodesStandardisierte numerische Codes (siehe Kapitel „REST“, Abschnitt 5) signalisieren Erfolg oder Art eines Fehlers.
Strukturierte FehlerantwortenGut gestaltete APIs liefern im Fehlerfall zusätzlich ein maschinenlesbares Fehlerobjekt (z. B. als JSON) mit Fehlercode und verständlicher Beschreibung.
Clientseitige BehandlungAsynchrone API-Aufrufe (siehe Kapitel „JavaScript“, Abschnitt 10) sollten Fehlerfälle explizit behandeln, um robuste Benutzeroberflächen zu gewährleisten.
