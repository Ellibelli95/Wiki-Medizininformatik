1. Was sind Web Components?

AspektBeschreibung
DefinitionWeb Components sind ein Bündel von Browserstandards, mit denen sich wiederverwendbare, gekapselte und framework-unabhängige HTML-Elemente erstellen lassen.
ZweckEigene, benutzerdefinierte HTML-Tags mit eigener Struktur, eigenem Verhalten und eigenem, gekapseltem Styling definieren – ohne Abhängigkeit von einem bestimmten JavaScript-Framework.
Nativer BrowserstandardIm Gegensatz zu Komponentenkonzepten einzelner Frameworks (z. B. React-Komponenten) werden Web Components direkt vom Browser nativ unterstützt.

2. Die vier Grundtechnologien

TechnologieAufgabe
Custom ElementsAPI zur Definition neuer, benutzerdefinierter HTML-Elemente mit eigenem Verhalten.
Shadow DOMKapselt die interne DOM-Struktur und das Styling einer Komponente vom umgebenden Dokument.
HTML-TemplatesDas <template>-Element definiert wiederverwendbare Markup-Fragmente, die zunächst nicht gerendert werden.
ES-ModuleStandardisierter JavaScript-Mechanismus zum modularen Import und Export von Komponentencode.

3. Custom Elements im Detail

AspektBeschreibung
DefinitionÜber customElements.define('mein-element', KlassenName) wird ein neues HTML-Element registriert, dessen Verhalten in einer JavaScript-Klasse implementiert ist.
NamenskonventionBenutzerdefinierte Elementnamen müssen einen Bindestrich enthalten (z. B. vital-anzeige), um Kollisionen mit zukünftigen Standard-HTML-Elementen zu vermeiden.
Autonome vs. angepasste ElementeAutonome Custom Elements erben von HTMLElement; angepasste („customized built-in“) Elemente erweitern ein bestehendes Standardelement wie <button>.

4. Shadow DOM

AspektBeschreibung
KapselungDer Shadow DOM erzeugt einen eigenständigen DOM-Teilbaum innerhalb eines Elements, dessen interne Struktur und Stile von außen nicht durch normale CSS-Selektoren beeinflusst werden.
Shadow RootÜber element.attachShadow({mode: 'open'}) wird die Wurzel des gekapselten Teilbaums erzeugt.
VorteilVerhindert unbeabsichtigte Stilüberschneidungen zwischen einer Komponente und der einbettenden Seite – besonders wertvoll in großen, aus vielen Fachanwendungen zusammengesetzten Portalen.

5. HTML-Templates und Slots

ElementBeschreibung
<template>Definiert inertes Markup, das beim Laden der Seite nicht gerendert wird, aber per JavaScript geklont und eingefügt werden kann.
<slot>Platzhalter innerhalb des Shadow DOM, an dem vom Nutzer der Komponente übergebener Inhalt (Light DOM) eingefügt wird.
AnwendungsfallErmöglicht es, den strukturellen Rahmen einer Komponente vorzugeben, während der konkrete Inhalt flexibel bleibt.

6. Lebenszyklus eines Custom Elements

CallbackAusgelöst bei
constructor()Erzeugung der Elementinstanz.
connectedCallback()Einfügen des Elements in das Dokument – typischer Ort für Initialisierung und erstes Rendering.
disconnectedCallback()Entfernen des Elements aus dem Dokument – Aufräumarbeiten wie das Entfernen von Event-Listenern.
attributeChangedCallback()Änderung eines beobachteten Attributs – ermöglicht reaktives Verhalten auf äußere Konfiguration.

7. Web Components vs. Frameworks

AspektWeb ComponentsFrameworks (React/Angular/Vue)
BasisNativer Browserstandard, kein Build-Schritt zwingend notwendigBibliothek/Framework mit eigenem Komponentenmodell, meist mit Build-Tooling
InteroperabilitätIn beliebiger Umgebung nutzbar, auch innerhalb von React/Angular/Vue-AnwendungenKomponenten i. d. R. an das jeweilige Framework gebunden
ÖkosystemKleiner, aber wachsendSehr groß, viele fertige Bibliotheken und Werkzeuge
Typischer EinsatzFramework-übergreifend wiederverwendbare UI-Bausteine, Design-SystemeKomplette, umfangreiche Single-Page-Anwendungen

8. Vorteile und Einsatzgebiete

VorteilBeschreibung
WiederverwendbarkeitEine Komponente kann in unterschiedlichen Projekten und Technologie-Stacks unverändert eingesetzt werden.
KapselungInterne Struktur und Styling beeinflussen die umgebende Seite nicht und umgekehrt.
LanglebigkeitDa Web Components auf Webstandards statt auf einem einzelnen Framework basieren, sind sie unabhängig von dessen Lebenszyklus.
Design-SystemeGut geeignet, um ein einheitliches, wiederverwendbares Komponenten-Set für mehrere, technologisch unterschiedliche Anwendungen bereitzustellen.

9. Web Components in der Medizin-IT

AspektBeschreibung
Wiederverwendbare WidgetsEine als Web Component gekapselte Vitaldaten-Anzeige oder Alarmleiste kann unverändert in unterschiedlichen, technologisch heterogenen Fachanwendungen (KIS, PDMS, Patientenportal) eingebettet werden.
Konsistentes ErscheinungsbildZentral gepflegte Komponenten sorgen für ein einheitliches Look-and-Feel über verschiedene, möglicherweise von unterschiedlichen Herstellern stammende Web-Clients hinweg.
Reduzierte KopplungDie Kapselung durch Shadow DOM verhindert, dass Stiländerungen einer Fachanwendung unbeabsichtigt eingebettete Komponenten anderer Systeme beeinflussen.

10. Begriffe und Quellen

BegriffBedeutung
Shadow DOMGekapselter, vom Hauptdokument isolierter DOM-Teilbaum einer Komponente.
Light DOMDer vom Nutzer einer Komponente übergebene, „normale“ DOM-Inhalt außerhalb des Shadow DOM.
SlotPlatzhalter im Shadow DOM zur Einfügung von Light-DOM-Inhalt.
Custom ElementBenutzerdefiniertes HTML-Element mit eigener Implementierung.
